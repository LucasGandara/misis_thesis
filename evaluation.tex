\chapter{Evaluation}
\label{cha:experiments}

In this chapter we turn our attention to the evaluation of the proposed transfer learning approach to develop agents with the capability to have general knowledge. We first describe the experimental setup, including the environments used for training and testing the agents (\fref{sec:setup}). Then, in the following chapters we present the results of the experiments, including the performance of the agents in both environments and the effectiveness of transfer learning in improving their performance. Finally, we discuss the implications of these results and their significance for future research in this area.

\subsection{Carla}
\label{sec:carla}
The first environment chosen was CARLA \cite{CARLA}, which provides a realistic and dynamic context for autonomous driving research. A reward signal was chosen to incentivize the agent to maintain a target speed of 50 km/h, the allowed road speed. The simulation environment for this study is the CARLA urban driving simulator.

Given that this thesis is employing a Twin Delayed Deep Deterministic Policy Gradient for decision-making, the action space has three continuous signals: steering the vehicle, Throttle the vehicle, or break, The CARLA simulator provides a way to manually shift gears and use the hand break, however in this experiment the car is only going to be able to move forward and the the gear shifting is going to be automatic. The vehicle has one sensor, an rgb frontal camera attached to the roof of the vehicle which produce images of 3 rgb channels of 480 x 640 pixels. The reward function is designed to encourage the agent to reach and sustain the desired speed of $50km/h$ while navigating through the environment. This approach ensures that the agent learns to balance the need for speed with the challenges of urban driving, such as handling turns and avoiding obstacles. To achieve this, the agent receives a penalty of $-1$ for every step taken that is at $50km/h$, the agent gets a penalty of $-200$ for a collision and a negative reward of $-15$ every time it changes lanes in a forbidden area.

The Turtlebot3 has a Lidar\footnote{Laser Distance Sensor: https://emanual.robotis.com/docs/en/platform/turtlebot3/appendix\_lds\_01/} to sense the environment on a range of 360 degrees around the robot, for the experiments, we reduced the range down to 24 samples. As mentioned in Algorithm \ref{al:td3}, two architectures of neural networks are used, one for the critic and one for the actor/policy.

\begin{figure}[h]
    \centering
    \includegraphics[width=0.6\textwidth]{./figures/critic_1_model.png}
    \caption{Critic network architecture.}
    \label{fig:critic_network}

Tha Critic network architecture is shown in \fref{fig:critic_network}, it begins with two input layers, \texttt{"state\_input"} for the batch of states and \texttt{"action\_input"} for the batch of actions, these inputs are followed by a a set of dense\footnote{A dense layer is a simple Layer of neurons in which each neuron receives input from all the neurons of the previous layer: \url{https://keras.io/api/layers/core\_layers/dense}.} layer to abstract their approximation and evaluate them separate. The state input is followed by \texttt{"state\_out"}, a dense layer of 16 units followed by a dense layer of 32 unit called \texttt{"state\_value"}. The \texttt{"action\_input"} is followed by a a dense layer \texttt{"action\_value"}, a dense layer of 32 units. Right after evaluating the state and action inputs, the two branches are concatenated into a single layer called \texttt{"concatenate"}, which combines the information from both inputs. This concatenated output is then processed by a dense layer with 64 units, followed by another dense layer with 32 units. Finally, the output layer, named \texttt{"dense"}, produces the final output of the network, \texttt{"critic\_value"}, which represents the Q-value for the given state-action pair.

The actor/policy network architecture can be seen in \ref{fig:actor_network} and starts with an input layer, which consists of the state information. This layer is followed by a dense layer with 256 units, which processes the input data. The next layer, named \texttt{"dense\_2"} also contains 256 units and further refines the information. After these layers, the data moves to the output layer, called "output," which has a single unit. This unit generates the final output of the network, representing the action to be taken based on the input state. Additionally, there is a multiply layer named "multiply," which also has 1 unit. This layer helps scale the output appropriately.

\end{figure}

The input state of the network is the measurement received from the Lidar sensor which consist of 24 measurement of detected distances in angles around the mobile base plus the $x$ and $y$ distance of the goal from the mobile base plus the heading angle $\theta$ of the robot with respect to the goal.

The reward functions was designed to encourage the mobile base to get from its start point to the goal point in the least amount of episodes possible, discouraging crashes against obstacles and keeping only on one side of the road. A crash of any kind is catastrophic for the episode. This function calculates a reward value that assists in guiding robot navigation by evaluating three primary factors: angular velocity, heading, and distance to the goal. The reward is designed to encourage efficient movement by balancing these elements.

The function takes several inputs:
\begin{itemize}
    \item \textbf{Heading angle}: Determines how well the robot's orientation aligns with the direction of the goal.
    \item \textbf{Angular velocity}: Measures the rate at which the robot adjusts its heading.
    \item \textbf{Start and current distance}: Helps assess whether the robot is moving closer to the goal.
    \item \textbf{Weight parameters}: Allow fine-tuning of the influence of angular velocity, heading, and distance improvement in the reward calculation.
\end{itemize}

The integration of these factors with adjustable weight parameters, produces a single reward value. This reward helps the robot make better navigation decisions by encouraging smooth directional adjustments, goal-focused movement, and minimizing unnecessary deviations.

To visualize and enact the driving paradigm change, we use an environment of a roundabout with line tracks emulated by walls as shown in \fref{fig:gazebo_tb3_environment}. The blue layer represent what the robot "sees" through the Lidar scans.

\section{Experiment Design and metrics to measure}
The experimental setup consists of multiple training phases. First, we trained two independent expert agents: one that learns to navigate exclusively on the right side of the road and another that learns to navigate exclusively on the left side. These experts start from one end of the environment and learn to reach the other end while maintaining their respective lane positions. After establishing these baseline experts, we conducted three additional training experiments: the first one, training a new agent to drive on the left side using the right-side expert as a knowledge base. The second, training a new agent to drive on the right side using the left-side expert as a knowledge base, and a final expert based training, a comprehensive agent that learns to navigate both sides of the road simultaneously. Each of these three agents was initialized with brand new actor and critic models. This progressive approach allows us to evaluate the effectiveness of transfer learning between different driving behaviors in the autonomous navigation context.

After establishing the expert agents, we conducted one final experiment focusing specifically on transfer learning. In this experiment, we trained a new agent to drive on the left side of the road by leveraging knowledge from the previously trained left-side expert. Unlike the independent training approach, this agent employed transfer learning techniques using the policy gradient transfer defined in Equation \ref{eq: pre train gradient pi} and the Q-function gradient transfer defined in Equation \ref{eq: pre train gradient Q}. To quantitatively evaluate the effectiveness of this knowledge transfer, we measured performance using three metrics as defined in Equation \ref{eq:tl_metrics}. This experiment allowed us to assess whether transfer learning could accelerate the acquisition of driving skills compared to training from scratch.

\begin{equation}
    \centering
    \begin{split}
        \text{Transfer ratio} & = \frac{\text{Ultimate performance with TL}}{\text{Ultimate performance with no TL}} \\
        Mastery               & = \text{Ultimate performance of the agent.}                                          \\
        Pedagogy              & = \text{How many less episodes the TL took.}
    \end{split}
    \label{eq:tl_metrics}
\end{equation}

Where $\text{Ultimate performance}$ refers to the return of the episode or the discounted cumulative reward achieved by the agent at the end of the episode. On each experiment, there are some metrics that are going to be saved to measure the performance of the agent such as the average reward per episode, the maximum reward achieved per episode, the time taken to complete the simulation without crashing, and the loss values accumulated by the networks during the training. The average reward is calculated by taking the mean of the rewards obtained in the last 50 episodes, while the maximum reward is determined by identifying the highest reward achieved in any episode. The time taken to complete the stage is measured in seconds, and the loss values are recorded for both the actor and critic networks during training.
